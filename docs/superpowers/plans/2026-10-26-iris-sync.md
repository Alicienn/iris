# Sync Between Devices — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two or more copies of Iris on the same Wi-Fi keep the same queue states, tasks,
goals, habits, own calendars, tags, rules, shared settings and notes, with no server of
ours: the queue state through IMAP keywords, the rest merged record by record after a
one-time pairing by QR code.

**Architecture:** Phase A writes and reads `$IrisWaiting` / `$IrisDone` through the existing
flag path (`Flags` bits, `op_journal`, `apply_flag_changes`). Phase B gives every synced row a
`sync_id` and a `sync_at` set by SQLite triggers that call an `iris_clock()` registered by
`iris-store`, with tombstones; `iris-store/src/sync.rs` reads changes since a peer's clock
and applies a batch in one transaction, newest change winning. Phase C adds the crate
`iris-peer` (pairing URI, handshake, sealed frames, messages, mDNS) and the app's
orchestration. Phase D merges note files by manifest. Phase E draws Settings › Devices.

**Tech Stack:** Rust 2021, rusqlite 0.37 (+ `functions`), tokio (`net`), `blake3`,
`chacha20poly1305` (XChaCha20Poly1305), `getrandom`, `zstd`, `serde_json`, `mdns-sd`,
`qrcode` (encoder, for the PC's code), Slint 1.17.

**Spec:** `docs/superpowers/specs/2026-10-26-iris-sync-design.md`; screens in
`..\Iris-design\android\sync.html` (Y1–Y7).

## Global Constraints

- The rules of `docs/superpowers/plans/2026-10-26-iris-mobile-index.md`.
- Keywords exactly `$IrisWaiting` and `$IrisDone`, on the newest message of the thread; To do
  is neither. Matching is case-insensitive.
- Migration 27: folders that accept keywords. Migration 28: sync columns, triggers,
  tombstones, peers, settings, snoozes.
- Clock string `{wall_ms:013}-{counter:06}-{device}` with `device` 16 hex characters;
  compared as strings; ties broken by the device part.
- `sync_id` = 32 hex characters from `getrandom`; seeded rows get fixed ids (`seed-area-1` …
  `seed-area-6`, `seed-calendar-personal`, `seed-vision`).
- Pairing URI `iris-pair:1?h=<ip>&p=<port>&d=<device id>&n=<name, percent-encoded>&k=<64 hex>`;
  valid 5 minutes, once. Six check digits. Session key
  `blake3::keyed_hash(secret, b"iris-sync 1" ‖ nonce_a ‖ nonce_b)`.
- mDNS service `_iris-sync._tcp.local.`, TXT `id=<device id>` only.
- Automatic sync every 10 minutes while Iris runs and a paired device is seen; listening only
  while Iris is open and on a local network.
- Passwords never written to a file; they travel only inside sealed frames.
- No `unsafe`; `iris-store` keeps `#![forbid(unsafe_code)]`.

## Review Focus

- Two devices whose clocks differ by ten minutes, both editing the same task offline: the
  hybrid clock orders by causality, not by the late wall clock, and both converge on the
  same row (Task B1 tests a peer 10 minutes behind observing a newer clock).
- A row deleted on one device and edited on the other after the deletion: the edit wins and
  the row comes back on the first device; edited before the deletion: it stays deleted
  (Task B4 tests both orders).
- A sync cut in the middle (Wi-Fi lost, app closed): nothing half applied; the next sync
  starts from the same `last_clock` and ends with the same state (Task B4 rolls back a batch
  that fails on its last row; Task C3 drops the socket mid-stream).
- A server that refuses keywords on one folder and accepts them on another: the states of
  the first travel in the device sync, the second through IMAP, never both for one thread
  (Task A2 tests a folder without `\*` in PERMANENTFLAGS).
- A second device that pairs with a QR code photographed from the screen by a third party
  on the same network: the check digits differ only if the key differs — so the protection
  is the five-minute, single-use window and the user's confirmation on the PC; the PC must
  show the name of the device that connected and ask before the first sync (Task C2 tests a
  second connection with the same code being refused).
